# 功能设计：BC路径 V1

日期：2026-10-24。当前为开发规格，尚未实现全部功能。

## 1. 范围与边界

首批服务BC普通课程高中生；中国籍国际生与加拿大本地学生均适用。IB/AP混合课程、BC海外学校、成人毕业、转学等特殊情况先记录并提示需要单独核验。

首批院校为UBC、SFU、Waterloo、Toronto、McGill、UVic、Alberta、McMaster。第一阶段重点在这些学校的计算机/数据、工程、商科、生命科学、社会科学/心理、人文传播相关入学项目；不是所有学校均提供上述全部直接入学项目。建库时必须先确认实际入学结构。

学校板块免费公开。注册是学生服务的访问条件，不等于订阅。收费与次数限制待产品验证后决定。

## 2. 角色与权限

| 角色 | 权限 |
| --- | --- |
| 游客 | 学校/专业介绍、筛选、官方来源、示例报告 |
| 已登录学生 | 仅自己的档案、成绩、成就、测评、情景、报告 |
| 内容管理员 | 学校与招生规则维护，不默认访问学生个人内容 |
| 系统任务 | 在授权范围内生成分析、保存任务状态 |

家长账号与分享权限后续设计。本版报告不公开，不默认创建可转发链接。

## 3. 核心业务流程

免费学校浏览 → 选择目标项目 → 注册/登录 → 建立BC学习档案 → 兴趣测评 → 录入成绩与成就 → 核对输入 → 条件检查与AI分析 → 保存报告 → 创建改善情景 → 比较与执行行动。

用户也可先测评再选择目标；没有测评结果也能检查申请课程条件，但不能声称已分析兴趣适配。

## 4. 注册与身份

- 邮箱验证、登录、登出、找回密码、会话失效处理。
- 密码交由成熟认证服务安全处理，不在应用表内存明文密码。
- API对每次学生数据读写校验用户身份与对象归属，前端隐藏按钮不构成权限控制。
- 退出后清除页面中的个人数据；其他用户不能通过替换URL读取报告。
- 提供导出与删除个人档案入口；未成年人隐私、服务条款和数据处理安排应在正式发布前确定。

## 5. 学校与招生规则库

### 结构

University → Campus → Faculty → AdmissionProgram → LaterSpecialization。

每个入学项目单独维护：适用课程体系、入学年份、必需课程及替代关系、最低成绩、均分算法、认可/排除课程、英语能力标准、补充材料、截止时间、入学后分流方式、官方来源与核验日期。

项目字段允许unknown；不能把空值理解为“无要求”。往年最低分、官方最低标准和竞争性参考区间分别存储，不能互相替代。

### 内容发布

草稿 → 核验 → 已发布 → 到期复核。只确认了大学一般要求时，不能标记该校全部项目规则已完整。规则变更保存历史版本，不覆盖旧报告的依据。

## 6. 专业测评

V1采用自编活动兴趣问卷，并补充学习偏好及价值观。若引入正式量表，需要先确认许可、题目版本和有效使用条件。

输出维度：偏好活动、学习方式、价值排序、专业探索理由、体验任务。学生可不认同结果并调整偏好。

推荐逻辑可先使用可解释的加权匹配，但不宣称测量精度。接近分数显示并列方向；未完成问卷不生成完整画像。兴趣结果不参与硬性录取条件判断。

## 7. 学术与成就输入

课程：标准BC课程ID、显示名称、年级、状态、当前成绩、最终成绩、修读时间、数据来源（学生自报/已核对）。模拟成绩存Scenario，不覆盖CourseRecord。

英语：考试类别、日期、总分和单项（如有）；在英授课时间；是否满足要求由项目规则确定，信息不全返回待核实。

成就：类型、名称、角色、日期、时长、行动、成果、反思、相关专业、事实或假设标记。第一版文本输入，不要求证书文件。

校验：成绩0—100，计划课程不能当已完成，同一课程重复时提示；活动不能有结束早于开始的时间；缺少成绩不得填默认0。

## 8. AI申请模拟：判断结构

用户希望得到“会不会被录取、差距是什么”。产品将其拆成四类可解释结果：

1. 资格与硬性条件：课程、最低要求、英语、必需材料。
2. 学术准备：按该项目的有效规则计算与解释课程表现。
3. 综合材料准备：仅在学校/项目实际考虑这些材料时分析成就、经历和表达。
4. 未来改进：改变课程、成绩或材料后，条件与准备情况如何变化。

### 阶段一：数据充分性检查

确认项目、年份、课程体系、课程记录、规则覆盖。缺少核心规则则输出“无法完成录取可能性判断”，仍可提供资料清单和官方入口。仅知道学生平均分不能生成校级录取结论。

### 阶段二：确定性条件检查

规则引擎负责所有可精确计算的内容：课程AND/OR、替代关系、状态、分数阈值、按校算法、英语条件。输出每项passed / pending / missing / unknown。

学生自报满足条件标为“按自报数据满足”，不能称已获大学确认。特殊豁免不自行批准。

### 阶段三：AI解释

模型只收到当前用户授权分析的结构化档案、项目规则和已检索来源。负责解释推荐理由、差距、行动优先级和材料表达，不新增招生要求，不伪造经历。

成就对不同项目作用不同：未确认考虑活动的项目，不把奖项换算成录取加分；只给学生个人发展建议。材料未提交时不判断其质量已经优秀。

### 阶段四：总体结论

优先使用以下结论，附解释与未知项：

- 资料不足，暂不能判断。
- 必要条件尚有缺口，建议先补齐。
- 已具备继续评估的基础，竞争性仍需核实。
- 有公开依据显示明显差距，建议调整准备或目标。

只有存在适用的公开竞争性数据时，才可增加“相对更具竞争力/仍有明显差距”的判断，并注明年份、适用对象与限制。正式录取结果由大学决定。

### 录取概率的后续条件

V1不生成无依据百分比。如未来要提供数字概率，需有合法获取、足量且可比的历史申请与结果数据，按学校/项目/课程背景/年份验证校准，展示区间、样本与外部变化影响。不能把LLM主观分数写成真实录取概率。

## 9. 情景模拟

基线为档案快照，用户创建多个情景：

- 提高某科预计成绩。
- 添加计划课程。
- 新增计划活动或改进补充材料。
- 更换目标校区、项目或入学年。

输出逐项变化：新增课程解决哪些缺口；目标成绩改变哪些参考；哪些要求仍未满足；哪些变化无法量化。假设成就不能被写入真实经历。

报告保留输入哈希、规则版本、模型版本、生成时间；重新分析生成新版本。规则过期时允许查看旧报告，但新模拟必须提示重新核验。

## 10. 报告输出协议

结构化字段：

```text
target: school/campus/program/intake
scenario: baseline_id, input_snapshot, actual_vs_hypothetical
coverage: checked_rules, unknown_rules, verified_at
eligibility_checks: requirement, status, evidence, source
academic_review: calculation_method, calculated_values, limits
interest_review: reasons, alternative_directions
achievement_review: program_relevance, evidence_gaps
overall: conclusion, supporting_reasons, unknown_factors
gaps: priority, issue, recommended_action, timing
comparison: changed_inputs, changed_findings, unresolved_items
provenance: sources, ruleset_version, model_version, generated_at
```

AI生成字段必须通过schema校验；模型失败不显示空白成功报告。规则检查结果与AI解释分开展示，便于查错。

## 11. 数据实体

| 实体 | 关键字段 |
| --- | --- |
| User | auth_id、email_verified、created_at |
| StudentProfile | user_id、grade、curriculum、status、intake、budget |
| CourseRecord | user_id、course_id、status、mark、term、source |
| Achievement | user_id、category、role、dates、actions、outcome、reflection |

学生实体均有user_id，并按归属隔离。日志不记录完整成绩与经历正文。

## 12. 建议接口

公开：GET /schools、GET /schools/:id、GET /programs/:id。

登录后：GET/PATCH /me/profile；课程与成就CRUD；POST /assessments；目标收藏CRUD；POST /scenarios；POST /analysis-jobs；GET /analysis-jobs/:id；GET /reports/:id；导出/删除档案。

分析提交使用幂等键，防止重复点击产生重复任务；限制输入长度与调用频率；服务端模型密钥不能放在前端脚本。

## 13. 实现阶段

### 阶段A：本轮设计交付

页面设计、功能规格、官方数据入口清单；保留早期静态原型。无正式注册、支付、真实AI或完整录取数据库。

### 阶段B：交互页面

按新信息结构制作公开首页、学校/项目详情、登录注册界面、学生工作台与完整模拟流程。可使用示例数据，但须醒目标注。

### 阶段C：可用MVP

接入真实认证、数据库和服务端AI。八所学校先选择少量具体入学项目，逐一核验BC规则；只对已核验范围开放完整分析。实现真实资料保存、异步分析、历史报告。

### 阶段D：扩展

更多项目、资料维护后台、完整双语、文件识别、经验证的竞争力模型、家长授权分享。按需要决定支付。

## 14. 验收案例

1. 游客能读学校介绍；直接调用学生API返回401。
2. 学生A不能读取学生B的报告，替换报告ID也不能绕过。
3. 缺少核心先修课程时，不能因兴趣或成就高而判定满足资格。
4. 计划课程显示待完成；空成绩不当0分；无效成绩禁止提交。
5. 修改模拟分数不改变真实成绩记录。
6. 未核验的项目不输出确定性录取判断或虚构概率。
7. 不考虑活动的项目不输出活动加分。
8. AI超时可重试；报告不重复创建；规则结果仍可单独展示。
9. 每条硬性判断可回溯官方来源与适用年份。
10. 草稿刷新可恢复，删除档案后旧访问不可继续读取个人内容。

# 参考功能框架与MaplePath映射

## 1. 公开可见结构

MYLS围绕模拟面试组织功能：按应用场景找项目，限时作答，查看评估、改写建议和复练进步。公共站点负责发现与说明，登录和练习入口进入app.myls.ai。来源：https://myls.ai/

公开导航层级：

```text
公共站点
├─ 首页：价值说明、报告演示、操作步骤、套餐、FAQ
├─ Products：六个训练场景
│  ├─ CASPer / MMI
│  ├─ 本科 / 研究生与MBA
│  └─ 求职 / IELTS口语
├─ Programs：搜索、分类、项目卡片
├─ Pricing：套餐及功能对比
├─ Blog / FAQ
└─ Sign in / Start free → 应用站点
```

首页报告演示包含五个视角：回答、评分、问题定位、优化答案、进步。其价值表达是“输入之后明确知道怎么改”，而不是只展示一个分数。该演示可在公开首页切换，不等于已验证登录后的报告实现。

## 2. 目录设计

目录采用项目搜索、分类胶囊与卡片。用户先按目标缩小范围，再进入具体项目。公开目录当前显示241项；首页宣传250+，二者不一致，不将其数字或数量复制给MaplePath。来源：https://myls.ai/program/

结构抽象：

```text
项目 = 名称 + 所属机构 + 分类 + 状态/试用标记 + 详情入口
筛选 = 搜索词 + 单一分类 + 结果数量 + 清除/空状态
```

不同项目图片有完整照片，也存在无图的浅色占位。MaplePath应显式设计占位图，不依赖图片缺失后的浏览器表现。

## 3. 商业与账户层

公开定价区分一次免费体验、定额使用与高频使用。功能对比中列出完整反馈、个性化面试、回放历史和报告分享。价格、权限与用量属于独立产品层。来源：https://myls.ai/pricing/

仅借鉴“先解释价值，再引导进入个人服务”的方式。MaplePath首轮不复制付费套餐、折扣倒计时或支付。

## 4. 主要产品闭环对照

| MYLS的设计思想 | MaplePath改编 | 第一轮实现原则 |
| --- | --- | --- |
| 以具体训练场景进入 | 从学校/专业方向或兴趣测评进入 | 游客自由浏览学校 |
| 找到具体项目 | 选校区、学院、入学项目 | 不只按学校做结论 |
| 用户实际回答 | 填档案、课程、成绩、成就 | 事实与假设分开 |
| 给出分项反馈 | 分开显示兴趣、硬性条件、学术和材料 | 不混成单一匹配分数 |
| 定位某句话的问题 | 定位某门缺失课程、某项材料缺口 | 每项结论能追溯输入和来源 |
| 提供可执行的改写 | 提供选课、目标成绩、探索任务 | 优先级清楚、行动具体 |
| 再练与进步比较 | 基线与改善情景比较 | 不改写真实成绩 |
| 个人训练记录 | 私有档案和报告历史 | 登录与数据隔离 |

## 5. MaplePath参考功能树

```text
MaplePath
├─ 免费公开层
│  ├─ 首页：价值 + 交互报告预览
│  ├─ 八校目录：搜索、省份筛选
│  ├─ 学校详情：介绍、校区、项目
│  ├─ 项目详情：入学路径、核验规则、来源
│  └─ 使用说明、示例报告、FAQ
├─ 学生层（登录后）
│  ├─ 档案：年级、BC背景、身份、目标
│  ├─ 专业兴趣测评
│  ├─ 成绩与选课
│  ├─ 成就与活动经历
│  ├─ 收藏与目标项目
│  ├─ 情景模拟：基线、假设、对比
│  └─ 报告：条件、差距、行动、来源、历史
├─ 管理层
│  ├─ 学校与项目资料
│  ├─ 招生规则核验与版本
│  └─ 任务、用量与审计
└─ 支撑层：认证、权限、数据库、规则引擎、AI解释
```

管理层是本项目需求，不是对MYLS后台的观察。

## 6. 首页交互演示的业务定义

建议五个标签：兴趣画像｜课程准备｜关键差距｜行动建议｜情景对比。

使用固定、虚构且清楚标注的学生案例，每个标签切换不同内容。页面可提供“查看完整示例”，但不自动生成真实学生结论。

例：学生清单少一门目标路径要求的课程 → 报告指出缺口 → 改善方案将其列为计划修读 → 对比显示缺失变为待完成。不能把计划课程加入后写成已满足录取条件。

## 7. 不应复制的内容

- 面试录音录像、答题倒计时，不属于本轮核心需求。
- MYLS的客户视频、机构标志、品牌、具体宣传数字。
- 未经验证的录取概率和结果承诺。
- 把MYLS按面试能力评分的逻辑直接当作大学录取模型。
- 为模仿竞品而引入本项目未决定的付费、真人辅导功能。

# MaplePath 枫向：本机环境、后台组件与免费部署方案

检查日期：2026-10-24。结论：可继续开发，无需购买服务器；小规模验证可按免费额度设计，但不能承诺无限使用或永久零费用。此轮是检查与方案，不安装系统软件、不创建云端账户、不部署。

## 2. 推荐架构

```text
GitHub私有代码仓库
        ↓ Git集成自动部署
Cloudflare Pages：公开页面 / 学生界面 / 管理界面
        ↓ /api/*
Pages Functions：会话验证 / 权限 / 规则检查 / AI代理 / 限流
        ├─ Supabase Auth：注册登录
        ├─ Supabase PostgreSQL：学生数据 / 学校项目 / 规则 / 报告
        └─ Workers AI：可选的免费额度模型解释
```

Git是版本管理，GitHub是代码平台，实际动态服务由Cloudflare和Supabase运行。不能只把网页上传GitHub就获得安全注册与数据库。

前端建议React + TypeScript + Vite；已有原型保留作为参考，不必为初期MVP引入完整服务端渲染框架。公开学校页面后续可按搜索需求预生成。后端采用Pages Functions即可，暂不另建常驻Node服务器。

## 3. 要补充的组件

| 组件 | 建议 | 第一版用途 |
| --- | --- | --- |
| 前端开发与构建 | React / TypeScript / Vite | 公共页面、学生空间、后台界面 |
| 表单与数据校验 | Zod；复杂表单再考虑React Hook Form | 防止无效成绩、缺失条件、AI格式错误 |
| 身份认证 | Supabase Auth | 注册、登录、找回、会话 |
| 数据库 | Supabase PostgreSQL | 档案、成绩、成就、规则、报告 |
| 数据权限 | PostgreSQL RLS + 服务端角色检查 | 学生只能读写自己数据 |
| API | Cloudflare Pages Functions | 验证身份、运行规则、调用AI |
| 后台 | 应用内/admin + Supabase管理面板 | 项目与规则维护，不必额外安装大型CMS |
| AI | 可替换模型适配层 + Workers AI可用免费模型 | 解释差距，规则仍由程序执行 |
| 质量验证 | Node内置测试；前端按需求加Vitest | 规则计算、权限、输入校验 |
| 发布工具 | Wrangler项目开发依赖 | 本地模拟与手动发布；Git集成可减少CLI需求 |

暂不需要：本地MySQL、常驻Redis、Kubernetes、付费向量数据库、本地大模型服务、文件OCR。使用云端Supabase开发项目时不强制Docker；完整本地Supabase才需要相应容器环境。

数据库迁移SQL必须入库，云端面板只用来管理和查看，避免规则与表结构无法复现。

## 4. 管理后台设计补充

建议路由：

- `/admin`：数据完整度、待核验项目、失败任务概况。
- `/admin/schools`：八校简介、校区和官方链接。
- `/admin/programs`：学院、入学项目、后续专业关系。
- `/admin/rules`：BC课程、替代关系、最低要求、均分算法、来源与入学年。
- `/admin/reviews`：草稿→复核→发布；过期标记；版本历史。
- `/admin/assessments`：题目与计分版本，不改写历史测评。
- `/admin/ai-usage`：调用次数、失败、限额、全局关闭AI开关。
- `/admin/audit`：谁在何时修改了什么规则，不记录学生正文。

角色：student、content_editor、admin。学生不能自行修改角色；编辑可维护公开内容，不默认读取学生档案。角色授予经管理端受控操作，不采信浏览器传入的isAdmin。

第一版可先以Git维护学校JSON和规则文件，并用Supabase面板管理基础数据；先完成权限与版本机制，再做全部后台页面，以控制开发成本。

## 5. 免费额度：核对后的边界

| 服务 | 当前官方免费范围 | 主要限制 |
| --- | --- | --- |
| Cloudflare Pages | 每月500次构建；不触发Functions的静态资源请求免费且不限量 | 构建与文件数量有上限 |
| Pages Functions / Workers Free | 合计每天100,000次动态请求 | Free CPU限制10ms/次；不是模型推理时间额度 |
| Supabase Free | 50,000月活认证用户、500MB数据库、1GB文件存储、5GB出口流量 | 最多2个活跃免费项目；低活跃7天可能暂停；免费版不等于生产SLA |
| Workers AI | 每天10,000 Neurons免费配额 | 按模型计量，不是10,000次请求；部分模型需付费，不纳入零预算方案 |

上述额度不能叠加解释为保证支持50,000名学生真实使用：数据库、出口和AI可能先达到限额。供应商可能调整规则，正式部署时再次核对。

## 6. 注册邮件：容易遗漏的一项

Supabase默认邮件服务只用于测试，当前仅向项目团队授权地址发信且约2封/小时，不能直接用于公众邮箱注册。

严格零预算封闭测试可先使用OAuth登录（例如Google，需配置应用与回调并验证目标用户可访问性），或仅限授权测试成员；不把Google设为唯一长期方案，以免部分中国用户无法使用。

正式开放邮箱注册与找回密码时，接入自定义SMTP，单独核对免费配额、发件域名和送达情况。若需要购买发件域名，该费用不能算永久免费。本轮不承诺邮箱注册可在零配置下免费开放给所有学生。

## 7. AI成本策略

规则判断与兴趣计分可在普通代码中完成，不消耗模型额度。

- 默认`AI_MODE=disabled`：规则报告仍可用，清楚说明未启用AI解释。
- 可选`AI_MODE=cloudflare`：仅选择免费可用、实测中文与结构化输出合格的模型。
- 首期建议每人每天2次AI分析；这是产品限额，不是供应商承诺。
- 全局配额、每人限额和并发数在服务端持久化控制，不能只存在页面或单实例内存。
- 用输入快照+规则版本缓存报告；相同输入不重复推理。
- 限制输入和输出长度；先计算规则，再请求模型解释。
- 配额耗尽时返回规则结果和明确提示，不自动切换付费模型。
- 不开付费计划、不启用自动充值；使用免费子域名，避免首期域名费。

实际能生成多少报告需根据具体模型和报告长度测量，不能用Neurons额度直接换算固定学生数。

免费模型质量不足时，保留规则分析；若未来更换收费API，必须先单独确定预算。免费主机不意味着所有外部模型免费。

## 8. 为什么不以GitHub Pages或Vercel Hobby作为正式方案

GitHub Pages是静态托管，官方明确不面向商业SaaS等用途，也不适合承载密码类敏感交易。可用于公开演示，但本项目的注册与学生数据服务不以它作为正式托管。

Vercel Hobby官方限制个人非商业使用。考虑项目可能成为教育服务产品，本方案不依赖该免费计划。

## 9. 部署步骤与停止条件

1. 整理本项目独立仓库，添加忽略规则；只放代码与公开资料。
2. 建立可复现依赖及锁文件，完成本地构建与规则测试。
3. 创建GitHub私有仓库、Cloudflare Free和Supabase Free项目。
4. 配置认证、数据库迁移与RLS；完成学生隔离和管理员权限测试。
5. 配置Pages Git集成：当前静态演示输出目录dist，无构建；未来Vite版本使用pnpm install --frozen-lockfile与pnpm build，并按云端构建版本确认包管理器兼容。
6. 仅把/api/*路由给Functions，静态文件不经过动态鉴权函数。
7. 云端保存密钥，Git不保存学生数据、数据库导出、SMTP密码或服务端密钥。
8. 预览环境用测试数据；正式开放前通过注册、隔离、报告与额度测试。
9. 免费额度不足时暂停相关功能或请求确定预算，不自动升级付费。

Supabase客户端公开URL/发布密钥可按其设计放前端，但必须配RLS；service_role/secret key只允许服务端，不能用VITE_前缀暴露。

当前项目仍有Sites的.openai/hosting.json，它仅属于之前的Sites配置，不是Cloudflare Pages配置。迁移时保留历史但不混用项目身份；本轮未发布，也未连接GitHub。

## 10. 可做出的成本承诺

开发和封闭试用可以以0美元托管预算为目标：免费子域名、免费计划、有限用户、限额AI、无文件上传、规则优先。超额时停止AI而非自动付费。

无法保证：永久免费、无限AI、无限邮件、生产SLA、免费自定义域名或所有地区均可稳定访问。以上不影响先完成原型与小规模验证。

# 页面设计：BC升学规划网站 V1

日期：2026-10-24。性质：供评审和后续开发的设计稿。

## 1. 产品定位与信息结构

面向BC课程10—12年级学生，连接自我认识、专业选择、学术准备与加拿大本科申请。界面现支持简体中文、繁體中文与English，顶部选择并记忆偏好；官方BC课程名保持英文。语言只改变展示，不改变已存课程与身份值。

网站分为两大区域：

1. 免费学校板块：无需注册，浏览学校、校区、学院、专业及申请路径介绍。
2. 学生板块：注册登录后建立档案、做专业兴趣测评、提交成绩与成就、进行AI申请模拟并查看报告。

主导航：学校与专业｜AI申请模拟｜如何使用｜登录｜免费注册。

“AI申请模拟”对游客可展示介绍与示例，开始输入个人档案时要求登录；不能先收集学生隐私再弹出注册。

## 2. MYLS参考与MaplePath视觉规范（已整合）

### 2.1 参考证据与适用范围

2026-10-24查看MYLS公开首页、项目目录、定价及CASPer页，检查实际渲染和部分DOM计算样式。未登录其应用，学生后台和管理后台不是竞品实测结果。离线截图和完整观察保存在[参考包](references/myls/README.md)，OpenCode无需访问外站。

实际MYLS风格为暖白底、黑色大标题、鲜蓝强调、胶囊CTA和轻边框演示卡。实测body为#FAFAF7、正文#14151B、主CTA为#3349FF，字体DM Sans；某桌面视口h1约60px。这些是参考证据，不是MaplePath品牌色。

MaplePath借鉴信息层级、首页双栏、可切换报告演示、搜索筛选目录和三步流程；保留自己的森林绿品牌。不要将原站蓝色和本项目绿色混成两套主色。

建议桌面主标题48—60px、区块标题28—36px、卡标题18—22px、正文16—18px、辅助12—14px；移动主标题32—38px，使用响应式字号。8px基础间距；区块垂直64—96px；卡片内边距24—32px；按钮高度44—48px。

### 2.3 响应式与通用交互

- ≥1100px：公共首页双栏、学校目录四列；768—1099px目录两列；<768px首页单列、文字先于报告演示、学校卡单列。
- 公共页面采用顶部导航；学生区域采用左侧导航，移动端可展开。
- 360px视口可操作；长英文课程名可换行；表格可横向滚动而不撑宽整页。
- 标签、筛选、表单具备键盘操作、可见焦点与可访问名称；状态不只靠颜色传达。
- 图片设定宽高比及占位，不使用MYLS截图、视频或学生照片作为上线素材。
- 不伪造评价、录取通知、成功率、客户数量或学校背书。

## 3. 公共页面

### P01 首页 `/`

目标：让家长与学生快速理解产品，并进入学校浏览或注册。

从上至下：

1. 导航：品牌、学校与专业、AI申请模拟、如何使用、登录/注册。
2. 主视觉：标题“从BC课堂，找到适合你的加拿大大学路径。”副文案说明兴趣、成绩、成就与专业选择。主按钮“开始我的规划”，次按钮“免费探索学校”。
3. 报告预览卡：与左侧标题并列，提供“兴趣画像｜课程准备｜关键差距｜行动建议｜情景对比”五个可点击标签；清楚标记虚构示例。
4. 八所院校入口：名称与省份，链接到免费学校详情。
5. 三步流程：专业探索测评 → 填写成绩与成就 → 模拟申请与查看差距。
6. 四个能力模块：认识自己、选专业、看准备、做模拟。
7. 示例对比：当前方案/改善后方案，展示课程与材料变化，不放虚构成功率。
8. FAQ：是否免费、国际生适用范围、是否保证录取、成绩如何使用。
9. 页脚：资料来源、隐私政策、条款、联系入口。

桌面首屏线框：

```text
Logo  学校与专业 / AI模拟 / 如何使用          登录 [免费注册]

从BC课堂，找到你的大学方向。       [示例报告：五个切换标签]
看见差距，知道下一步。             [对应内容：画像/条件/差距]
副文案 + 三条简短价值说明          [行动或情景变化]
[开始我的规划 →] [免费探索学校]
```

两句标题分别用正文色与森林绿强调。演示卡为白色圆角、浅边框、柔和阴影，标签轨道浅色、当前标签突出。此卡优先于纯装饰指南针；抽象路径图仅作辅助。

示例应呈现“缺少课程→计划修读→仍待完成”的真实状态逻辑；不把假设课程当已满足条件。标签切换不调用AI，不要求登录；“查看完整示例”进入公开示例报告。尊重减少动画偏好，不强制自动轮播。

第一轮不设置付费套餐，以“免费学校探索”和“注册后的个人规划”说明服务边界。没有真实证据时省略用户评价模块。

游客点击开始规划进入注册页；登录后回到原目标页面。

### P02 学校目录 `/schools`

免费且无需登录。首批八所学校：UBC、SFU、Waterloo、多伦多大学、McGill、UVic、Alberta、McMaster。

搜索：中英文校名。筛选：省份、专业大类、校区（有资料时）、资料完整程度。收藏操作提示登录。

卡片信息：学校常用简称、正式英文全名、中文全名、校徽/纹章、省份、城市（有核验资料时）、简短介绍、专业方向与资料状态。校徽保留原比例并提供来源及替代文字；英文界面不重复中文名。学校详情尚未实现时，按钮链接至已有目录或官方要求，不制造失效入口。没有来源支持时，不展示排名、就业率或总费用数字。

视觉结构：左对齐大标题与说明 → 宽搜索框与结果计数 → 分类胶囊 → 学校卡片网格。省份胶囊显示全部、BC、ON、QC、AB；选中状态用主色并保留文字标识。其他筛选可折叠，避免首屏过密。

卡片上部为获准校园图或统一占位图，下部为中英校名、城市、省份与简述。整卡主要导航到详情，收藏为独立按钮，避免嵌套链接。图片缺失必须有明确占位。计数反映当前筛选结果，不硬编码为八所。

空状态：解释筛选过窄并提供清除筛选。学校并列展示，不默认标为冲刺/匹配/保底。

### P03 学校详情 `/schools/:school`

顶部：校名、城市/省份、学校简介、官网链接、最近核验日期。

页面沿用公共落地页模板：面包屑 → 学校标题/介绍与概览卡 → 校区与项目 → 申请路径 → 来源 → 模拟入口。

页内标签：学校概览｜学院与专业｜申请路径｜费用与生活｜常见问题。

内容：

- 校区及本科入学结构；区分入学项目与后续专业。
- 本科项目目录，可按专业大类筛选。
- BC课程申请一般说明、英语能力要求入口。
- 项目差异提示：课程条件、补充申请、作品集/面试等由项目决定。
- 国际学生与本地学生相关费用分别展示；未核验项目标记待核验。
- “用我的档案模拟此项目”：登录后进入目标选择；游客进入注册。

### P04 项目详情 `/schools/:school/programs/:program`

这是申请模拟的最小目标单位，不能只选择学校。

展示：校区、学院、入学项目、学位、可能的后续专业、BC先修课程、均分计算说明、英语要求、补充材料、费用、时间节点、官方来源。

展示顺序：项目与所属校区/学院 → 条件清单 → 英语与材料 → 入学后路径 → 来源 → 登录模拟。

每项规则显示适用入学年份与核验状态。无法确定的字段明确显示“待核实”。

### P05 使用说明与示例 `/how-it-works`

三步介绍、一份虚构学生的完整示例报告、数据使用说明。明确“申请模拟是辅助判断，最终决定由大学作出”。

## 4. 账户页面

### P06 注册 `/register` 与登录 `/login`

注册：邮箱、密码、确认密码、必需条款与隐私确认、邮箱验证。可后续接入Google登录。市场推广同意单独选择，不预选。

登录：邮箱与密码、找回密码、验证状态反馈。未登录只能看公开介绍与示例报告。

注册成功保留来源目标，例如返回UBC具体工程项目的模拟入口。找回密码不泄露某个邮箱是否注册。

## 5. 学生页面

桌面采用左侧导航：规划总览｜我的档案｜专业测评｜课程成绩｜成就经历｜目标项目｜AI申请模拟｜报告记录。移动端使用可展开菜单。

### S01 规划总览 `/student`

内容：资料完成进度、下一步操作、收藏项目、最近模拟、行动计划。新用户只展示开始路径，不生成默认个人评分。可载入“示例档案”，必须清楚标明示例并在覆盖前提醒。

### S02 我的档案 `/student/profile`

字段：年级、课程体系、所在省份、计划入学年、申请身份、已接受英语授课的时间、意向地区、年度预算。无需采集护照号或家庭精确收入。

明确BC课程与国际学生身份可同时成立。没有足够信息时英语条件为“待核实”，不自动判断豁免。

### S03 专业测评 `/student/assessment`

分三段：活动兴趣、学习偏好、价值观。显示进度、可返回、自动保存草稿。

结果：兴趣维度、优先探索专业、推荐理由、可能不喜欢的学习内容、一个体验任务。学生可收藏/排除专业，并说明偏好。自编题只称兴趣探索，不声称标准化人格诊断。

### S04 课程与成绩 `/student/academics`

表格：课程名、年级、在修/已完成/计划、当前成绩、模拟目标成绩、成绩时间。真实记录与模拟记录分开。

支持手动添加、删除、重复课程检查；后续才做成绩单上传与识别。显示必修条件提醒与缺失信息。平台均分标明计算方式，不冒充某校录取均分。

### S05 成就与经历 `/student/achievements`

条目：活动类别、名称、时间、持续时长、角色、具体行动、结果/成果、个人反思；奖项额外记录颁发方与层级。支持草稿与编辑。

AI可帮助整理表达，但不编造经历、不把活动数量机械换算成录取加分。

### S06 目标项目 `/student/targets`

从八所学校选择具体校区、入学项目和方向，最多保存五个并列目标。信息不完整的项目可收藏，但在模拟前提示规则覆盖不足。

### S07 AI申请模拟 `/student/simulate`

四步向导：

1. 选择学校、校区、项目与入学年份。
2. 选择真实档案或创建“假设情景”；成绩与经历分别标注实际/预计/假设。
3. 核对输入摘要、缺失信息、规则覆盖状态。
4. 生成报告：先运行条件检查，再生成解释。

结果区包括：当前判断、判断依据、硬性缺口、学术差距、成就与材料准备、未知因素、建议行动，以及模拟改善后的变化。

页面状态：草稿、校验失败、排队、分析中、成功、资料不足、失败可重试。费用或次数限制尚未定，不放付款页。

### S08 报告详情 `/student/reports/:id`

首屏：项目与情景名称、生成时间、规则版本、总体结论与可信依据。

分区：条件清单｜专业适配｜学术准备｜成就材料｜差距排序｜行动计划｜情景对比｜来源。

主操作：创建改善方案、重新模拟、保存报告、打印PDF。默认私有。跨用户访问应返回无权限。

“是否会录取”的呈现：说明可判断的条件与可能性等级，并显示未知项；不作确定录取承诺。没有可靠校准数据时不显示百分比。

## 6. 报告布局线框

```text
目标：学校 / 校区 / 入学项目 / 入学年       情景：当前档案
结论：先补齐必要条件 / 可继续评估 / 存在明显差距 / 资料不足
依据摘要：课程规则覆盖范围、缺少的信息、数据核验时间
---------------------------------------------------------
专业兴趣        学术准备        成就与补充材料
匹配理由        课程与成绩      相关经历与待完善材料
---------------------------------------------------------
优先差距        建议行动        预期作用 / 完成时间
---------------------------------------------------------
当前方案 ↔ 改善方案：课程、目标成绩、材料变化与未解决项
---------------------------------------------------------
官方来源、规则版本、判断局限
```

## 7. 页面验收

- 游客可完整阅读学校与项目介绍；学生所有页面受服务端登录权限控制。
- 注册后返回原项目；草稿可恢复，刷新不丢失已保存内容。
- 课程与假设情景不混写；成就按事实与模拟区分。
- 报告能追溯输入、规则、来源，显示资料不足状态。
- 360px宽度无主要内容溢出，表单有标签，键盘可操作，错误提示可读。
- 未完成数据接入的按钮不得伪装为已完成AI分析。

- 首页双栏及五标签示例可用；目录搜索、筛选、结果计数和空状态一致。
- 视觉统一采用本文件token；离线参考截图仅供内部设计，不作为产品图片。
